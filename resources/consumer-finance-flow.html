系统如何分层协作

业务服务负责领域规则，基础设施提供可靠积木，横切能力贯穿每次调用。边界清楚，才便于独立演进与故障隔离。

业务域服务

按业务能力拆分，而不是按数据库表拆分。

客户域 客户 / KYC / 影像
信贷域 申请 / 授信 / 合同
资产域 借据 / 放款 / 还款
风险域 反欺诈 / 决策 / 模型

数据与消息底座

不同数据形态，选择不同存储职责。

云原生运行底座

让服务可调度、可伸缩、可恢复。

Kubernetes 编排与自愈
Service Mesh 流量治理
配置 / 密钥中心 动态配置
CI/CD + GitOps 可回滚发布
指标 MetricsPrometheus + Grafana：RED/USE、业务成功率、SLO
日志 Logs结构化日志 + traceId，集中检索并脱敏
链路 TracesOpenTelemetry：定位跨服务慢点与错误传播
安全 Security零信任、最小权限、密钥轮换、审计留痕

云原生原则，不是技术名词清单

每条原则都要落到信贷业务的可验证结果：高峰不崩、失败可恢复、变更可回滚、决策可解释、数据可追溯。

风险系统：贯穿全程的“第二条主线”

风控不是授信审批处的一次调用。从设备、身份、额度、支用、交易到贷后预警，每一步都在累积证据与反馈。

六层风险防线

理解以后，再把它记住

用“业务站点 + 系统动作 + 失败补偿”三问法复习，不背孤立组件。

抽认卡

先回答，再翻面；系统会随机换题。

一条主线，四个反复检查

每经过一站，都问同样的四句话。

谁来？做什么？失败怎么办？如何看见？
  1. 谁来：入口与身份是否可信、权限是否最小？
  2. 做什么：领域边界、数据归属、同步还是异步？
  3. 失败怎么办：超时、重试、幂等、补偿、降级是否成套？
  4. 如何看见：指标、日志、链路、审计是否能还原现场？
